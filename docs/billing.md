# 고객사 월별 청구 (v1)

## 진입점과 권한

- `결제 > 청구`: `/admin/billing`, `/t/[tenantSlug]/admin/billing`.
- 플랫폼 관리자(`profiles.platform_role = admin`)만 계약/청구일 설정, 청구 확정, 전액 입금 확인 가능.
- 고객사 오너는 자기 고객사 조회만 가능. 코치/매니저/일반 회원은 접근 불가.
- 서버 액션에서 인증/역할/tenant를 재확인하며, DB 읽기에도 RLS가 적용된다. 일반 클라이언트의 직접 쓰기와 청구 확정 RPC 실행은 금지한다.

## 산정

- 고객사 기본 청구일 18일, 기본 단가 7,500원. 신규 계약에서 단가를 별도로 보존한다.
- 고객사별 당월 정규 청구 인원이 **51명 이상**이면 전체 정규 항목에 6,500원 단가를 적용한다(50명까지 기본 7,500원). 운영자/관계자 제외, 같은 계약 이동 중복 제거, 개인 1인 상한을 반영한 인원 기준이다. 별도 계약 단가가 이미 6,500원 미만이면 인상하지 않는다. 명단 조정으로 51명 경계를 넘나들면 원래 기본/계약 단가에서 재계산한다. 중간 합류 추가분은 당월 할인 기준 인원에 넣지 않고 원 청구서의 확정 단가를 유지한다. 확정 청구서는 재계산하지 않는다.
- 프로그램 선정은 **선택한 청구월 1일~말일(한국시간)에 운동 후기가 1건 이상 등록된 프로그램**만 대상이다. 월별 분석과 같이 `program_session_reviews.created_at`을 사용하며 공개 여부, 프로그램 시작/종료일, 담당 코치, 답변 여부로 제한하지 않는다. 현재 월은 조회 시점까지 등록된 후기로 예상액을 산정한다.
- 선불 청구: 8월 18일은 8월 후기 조건과 8월 18일~9월 17일 이용권, 9월 18일은 9월 후기 조건과 9월 18일~10월 17일 이용권 기준이다. 기존 확정 스냅샷은 재작성하지 않는다.
- 선정된 프로그램의 전체 등록 회원을 이용권 이력으로 산정하며, 후기 미작성 회원도 포함한다. 후기가 없는 프로그램의 이용권만 가진 회원은 제외한다. 같은 계약에서 일부 프로그램만 후기 조건을 충족하면 그 프로그램의 인원만 합산한다.
- 이번 청구일 00:00 KST부터 다음 청구일 00:00 KST 직전까지의 이용권 보유 기간과 겹치면 월 전액. 종료된 이용권을 임의로 연장하지 않는다.
- 29~31일은 해당 월에 그 날짜가 없으면 말일로 보정한다.
- 같은 계약에 연결한 프로그램은 user_id로 중복 제외. 별도 계약은 독립 산정한다.
- 계약이 없는 프로그램도 기본 단가로 자동 산정하여 상단 합계와 참여자 상세에 표시한다. 프로그램별로 회원 중복을 제거하며, 별도 프로그램은 독립 합산한다. 같은 프로젝트의 런/스테이션을 합쳐 한 번만 청구하려면 묶음 계약을 등록한다.
- 등록된 계약이 있으면 그 계약의 단가·기간을 우선하며, 계약 시작 전/종료 후에 자동 산정으로 되돌아가지 않는다.
- `billing_settings.excluded_program_ids`에 설정된 프로그램은 자동 산정과 계약 산정에서 모두 제외한다. 운동 기록이나 프로그램 자체는 변경하지 않는다. 제외 목록은 확정 스냅샷에도 보존한다.
- `billing_settings.single_member_program_ids`는 프로그램별 **최대 1명분 청구** 설정이다. 명단은 모두 보존하지만 청구 대상자가 1명 이상이면 1명 × 단가, 0명이면 0원이다. 자동 산정과 단독 계약, 월별 재조회, 수동 명단 조정 및 확정 스냅샷에 동일하게 적용한다. 이 설정이 있는 프로그램은 다른 프로그램과 묶음 계약으로 등록할 수 없다.
- `○○님 전용 하이록스 프로그램` 이름 형식은 모두 개인 프로그램으로 자동 분류하여 최대 1명분만 청구한다. 앞뒤/구분 공백을 허용하며, 새로 생성한 같은 형식의 프로그램에도 적용한다. 수동 지정 ID와 자동 분류 ID를 합쳐 계산하고 확정 스냅샷에 보존한다. 일반 그룹 프로그램에는 적용하지 않는다.
- 기간제는 첫/마지막 청구월로 회차 제한(12주 계약은 3회 설정). 지속형은 마지막 청구월을 정할 때까지 반복.
- 후기가 없는 월은 청구 대상에서 빠지며 기간제의 마지막 청구월이 자동 연장되지는 않는다.
- 청구일 이후에만 수동 확정 가능. 자동 발행/메일/출금/세금계산서 발행은 구현하지 않았다.
- 중간 합류: 이전 선불 청구의 프로그램/기간에 속하지만 확정 명단에 없던 새 참여자는 다음 청구에 원래 이용월·참여일·당시 단가를 보존한 추가 항목으로 합산한다. 다음 청구를 건너뛰면 이후 미확정 청구에서 미청구 항목을 수집한다. 이전 청구가 확정되지 않았다면 해당 월 예상액에 계속 반영하며 별도 이월하지 않는다.
- 이미 확정 명단에 있던 회원(명시 제외 포함), 이동 회원, 이미 추가 청구한 회원은 같은 원래 이용월에 재청구하지 않는다. 1인 프로그램은 원 청구와 과거 추가 청구를 합쳐 최대 1명분이다. 현재 관계자/프로그램 제외는 미확정 추가 항목에도 반영한다. 기존 후불 스냅샷은 자동 이월 대상이 아니다.
- 중간 합류 보고는 이전에 확정한 선불 청구서에 포함된 프로그램을 기준으로 한다. 확정 당시 선정되지 않았던 새 프로그램을 소급 추가하는 기능은 별도 범위이다. 상단 인원은 정규 인원이며 이전 월 추가 인원분·금액은 별도 표시한다. 합계 금액은 정규 이용료와 추가 이용료를 포함한다.
- 미가입 사전등록자는 산정하지 않는다. 운영 계정은 현재 역할 기준 기본 제외. 계약별 참여자 상세에서 수동 포함/제외 및 사유 기록 가능.
- 명시적으로 합의한 사전등록 첫 청구월은 `billing_preregistration_terms`에 저장한다. 가입 연결된 회원의 해당 프로그램·사전등록 이후 이용 구간에만 적용하며, 첫 청구월 이전 이용은 추가 청구로 이월하지 않는다. 운영 명단과 분리된 청구 설정으로 일반 오너/매니저는 수정할 수 없다. 다른 명단에는 자동 적용하지 않는다.
- 2026-09-11 요청 명단 13명(잠실 스테이션 4명·당산 9명)은 9/14 00:00 KST 이용 시작, 9/18 첫 월 1회 청구로 합의했다. 9/14~17은 별도 추가 청구하지 않는다. 당시 가입 연결 2명의 기존 8/17 시작 이용권 및 청구 이력도 함께 정정했다. 상세는 `docs/preregistration-correction-2026-09-11.md` 참조.
- 관계자 지속 제외: 참여자 상세의 `다음 달에도 청구 제외`에서 사유와 프로그램/고객사 전체 범위를 저장한다. 기본값은 해당 프로그램이며, 묶음 계약에서는 실제 프로그램을 하나 선택한다. `청구 제외` 탭에서 목록과 사유를 확인하고 해제할 수 있다. 등록·해제는 기존 청구 변경과 동일하게 플랫폼 관리자만 가능하며 오너는 조회만 가능하다.
- 지속 제외는 모든 미확정 청구와 이후 월에 적용된다. 고객사 전체 제외는 새로 참여하는 프로그램에도 적용되고, 프로그램 단위 제외는 다른 프로그램의 참여에 영향을 주지 않는다. 묶음 계약에서 제외되지 않은 프로그램도 이용했다면 그 회원은 한 번 청구한다.
- `청구 제외 → 회원 검색하여 제외 추가`에서 현재 고객사의 전체 유저를 이름/이메일/전화번호로 검색한다. 빈 검색어는 전체 조회, 10명씩 페이지 이동을 지원한다. 청구월·후기·이용권 유무로 제한하지 않으며, 회원 정보만 등록된 계정도 미리 제외할 수 있다. 검색 선택 시 고객사 전체가 기본값이고 특정 프로그램으로 바꿀 수 있다. 검색도 플랫폼 관리자만 가능하며 서버에서 인증한 고객사/행위자를 사용한다. 기존 회원 검색 RPC를 재사용하고 브라우저에는 식별용 이름·이메일·전화번호만 반환한다. 저장 시 DB 트리거가 고객사 소속을 재검증한다.
- 지속 제외 회원을 일회성 포함으로 덮어쓸 수 없다. 먼저 지속 제외를 해제해야 한다. 프로그램/고객사 전체 제외가 겹치면 하나만 해제해도 다른 제외는 유지된다. 개인 1인 프로그램도 청구할 회원이 모두 제외되면 0원이다.

## 이력과 보존

- `billing_access_periods`: 이용권 생성/기간 변경/비활성화/재활성화/삭제를 DB 트리거로 기록한다. 앱이 열려 있지 않아도 기록되며 화면 조회 시 예상액을 재계산한다.
- 기존 활성 이용권은 현재 저장된 이용 기간으로 초기화한다. 기존 비활성 이용권은 프로그램 변경 이력에 종료 시점이 있으면 사용하고, 없으면 `needs_review`로 표시한다. 과거에 기록되지 않은 활성/비활성 반복 이력은 복원할 수 없다.
- 불확실한 과거 이용 기간은 운영자가 포함/제외를 정해야 청구를 확정할 수 있다.
- 확정 시 명단/단가/기간/사유를 JSON 스냅샷에 저장. 고객사·월별 유일성으로 중복 확정 방지. 금액/명단 변경·삭제를 DB에서 차단한다.
- 프로그램 선정 규칙, 후기 기준월, 해당 프로그램 ID/제목/후기 건수도 스냅샷에 보존한다. 확정 전 재조회 때 후기 조건이 바뀌면 오래된 화면의 확정을 거부한다. 이 규칙 도입 전 확정된 청구서에는 소급 적용하지 않는다.
- 실제 입금 확인은 전액 확인만 지원. 부분 입금, 취소/정정 청구서는 후속 범위이다.
- `billing_member_exclusions`에 사유, 범위, 활성 상태, 생성/최근 변경 시각, 마지막 변경자를 저장한다. 해제 시 행을 삭제하지 않고 비활성화한다. 조회/계산은 tenant별로 제한하며 직접 클라이언트 쓰기를 금지한다. 확정 스냅샷에는 당시 적용된 제외 사유와 범위, 전체 참여 명단이 포함된다.

## 초기 운영 제한

- 실제 고객사 계약과 청구서는 자동 생성/이관하지 않는다. 예상액 조회에 계약 등록은 필요 없으며, 별도 단가·프로그램 묶음·3회 제한 등이 필요한 경우에만 계약을 등록한다. 자동 산정 항목은 회차를 임의 추정하지 않고 매월 후기 조건으로 선정한다.
- 청구일은 계약 등록 또는 최초 청구 확정 전에 설정한다. 이후 청구일 변경은 기간 겹침/누락을 막기 위해 제한한다. 주기 전환은 별도 설계가 필요하다.
- 사용자 요청에 따라 xon-training의 `[DANGSAN] PROJECT SHENZHEN: 8-Week HYROX CAMPAIGN`(84f68835-ac5f-48a1-bd65-118cc731d284)을 청구 제외 설정에 저장했다.
- 최초 요청으로 이정민 프로그램 ID를 수동 지정했고, 후속 요청으로 같은 이름 형식의 개인 프로그램 전체에 1인 청구 자동 규칙을 적용했다. 추가 인원의 이용권·운동 기록·코치 역할은 변경하지 않는다.
- 이동 중복 제거 요청에 따라 잠실 12주 러닝·스테이션을 통합 청구 계약(`c793c188-54c4-4987-9164-a472ec5eb0bf`)으로 연결했다. 이용 시작 2026-08-17, 선불 청구 2026-08~2026-10 3회, 기존 단가 7,500원을 유지한다. 다른 프로젝트/개인 프로그램과는 별도 청구한다. 계약만 저장했으며 청구서 확정이나 실제 결제는 하지 않았다.
- 당산 12주 프로그램도 단독 기간제 계약(`7188910d-8fe7-4a99-a878-1ae952757a3e`)으로 연결했다. 이용 시작 2026-08-17, 첫 청구 2026-08, 마지막 청구 2026-10으로 각각 1/3·2/3·3/3회 표시한다. 기본 계약 단가 7,500원에 고객사 합산 51명 이상 할인(6,500원)이 동일하게 적용된다. 2026-11부터 정규 청구는 종료되며 미청구 중간 합류 추가분은 기존 이월 규칙을 따른다.
- 기존 계약은 종료월만 앞당길 수 있다. 단가/연결 프로그램 변경이나 연장은 이후 월에 새 계약으로 등록한다.
- 확정된 월에 새로운 계약을 소급 추가하지 않는다. 확정 이후 소급 변경은 별도 정정 프로세스가 필요하다.
- 테스트용 계약·청구서·입금·권한 변경은 트랜잭션에서 롤백하여 실제 고객사 데이터로 남기지 않는다.

## 검증

- `pnpm test:billing`: 순수 계산 회귀 테스트. `pnpm test:billing -- "18일 선불"` 또는 `pnpm test:billing -- "중간 합류"`로 선택 실행.
- `pnpm exec tsc --noEmit --incremental false`, `pnpm lint`, `pnpm build`.
- DB: 소유자 읽기/그 외 역할 차단, 직접 쓰기 금지, 기간 중복 계약 차단, 청구일 고정, 이용권 변경 이력, 청구서 중복 및 수정 차단, 입금 중복 방지 확인.
