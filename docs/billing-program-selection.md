# 월별 청구 프로그램 선택

플랫폼 관리자는 청구 → 프로젝트별 이용료 → **청구 프로그램 설정**에서 전체 프로그램을 검색하고 체크할 수 있다. 오너 등 다른 역할은 편집할 수 없다.

- 기존 월별 후기 자동 감지를 초기값으로 사용한다.
- 체크 변경은 해당 청구월에만 저장된다. 다음 달에는 자동 감지와 기본 청구 제외 설정을 사용한다.
- 직접 포함은 후기 유무 및 기본 프로그램 제외보다 우선한다. 직접 제외는 해당 월 예상 청구에서 프로그램을 제외한다.
- 계약 기간, 단가, 이용 기간, 사전등록 첫 청구월, 회원 제외, 통합 계약 중복 방지와 1인 청구는 계속 적용된다. 프로그램 선택만으로 청구 인원이 생기지는 않는다.
- **자동 감지로 되돌리기** 후 저장하면 해당 월의 수동 선택을 해제한다.
- 확정된 청구서는 수정하지 않는다. 수동 선택과 실제 후기 수를 확정 스냅샷에 보존한다.

`billing_program_selections`에 월별 포함/제외 배열과 수정자·수정 시간을 저장한다. 직접 클라이언트 접근은 차단하고 서비스 전용 RPC에서 플랫폼 관리자, 고객사 프로그램 소속, 선택 중복과 확정 여부를 검증한다. 청구 확정과 선택 저장은 같은 설정 행을 잠그고, 확정 시 선택이 달라졌으면 오래된 스냅샷을 거부한다.

DB 적용 후 별도 트랜잭션에서 정상 저장, 중복 제거, 매니저·다른 고객사 차단, 확정월 변경 및 오래된 스냅샷 거부를 검증하고 전부 롤백했다. 실제 청구 프로그램 선택이나 청구서는 변경하지 않았다.

보안 검사에서 이 테이블의 [RLS 정책 없음 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)가 표시된다. 서비스 전용 테이블로 인증·비인증 클라이언트의 테이블 권한과 RPC 실행 권한을 모두 회수했으며, 클라이언트용 RLS 정책은 의도적으로 두지 않았다.

검증: `pnpm test:billing`, `pnpm test:billing-users` 및 두 명령의 `-- "프로그램 선택"` 필터. 기존 매니저·요청 복구·월간 통계 검사, lint, 타입 검사, 프로덕션 빌드도 실행한다.
