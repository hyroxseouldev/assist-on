# 참여 프로그램 변경 페이지 분석

2026-09-11 · 로컬 실행 화면 `/admin/program-changes` · 엑스온 오너 계정

회원 검색, 변경 불가 상태, 활성 이용권의 변경 폼, 최종 확인 모달까지 직접 확인했다. 실제 변경 적용은 실행하지 않았다. 현재 화면과 저장된 스크린샷, 관련 소스를 근거로 분석했다. 운영 배포본과 동일하다고 가정하지 않았다.

기본 흐름은 짧고 명확하지만, 운영자가 정확한 회원·이용권·기수를 확인하는 정보가 부족하다. 상태 판정 통일, 자동 선택 제거, 확인 정보 보강을 우선 권장한다.

## 확인한 단계

1. 회원 검색·목록 — 개선 필요. 이름/이메일/휴대폰 검색은 제공되지만 변경 가능한 회원을 구분할 상태와 필터가 없다. 186명, 19페이지이며 카드 높이 때문에 첫 화면에서 페이지 이동 버튼이 보이지 않았다. 이메일이 있으면 휴대폰은 표시되지 않아 Apple 가림 이메일 및 동명이인 식별에 불리하다.
2. 변경 불가 회원 선택 — 우선 개선. 목록에는 프로그램명이 있지만 상세에는 “변경할 수 있는 활성 프로그램이 없습니다”만 나온다. 만료·시작 전·비활성 중 어떤 이유인지 알 수 없고 다음 행동도 없다.
3. 활성 회원의 프로그램·기수 선택 — 우선 개선. 회원 선택 직후 대상 프로그램과 1기가 자동 선택되어 확인 버튼이 활성화된다. 기수 선택지는 이름만 표시한다. 개인 전용 프로그램도 다른 프로그램들과 함께 후보에 나타난다.
4. 최종 확인·취소 — 기본 구조 양호, 확인 정보 보강 필요. 모달에서 프로그램명, 즉시 적용, 종료일 유지 안내를 확인했다. 취소로 복귀할 수 있었다. 선택한 기수, 기수 시작일, 회원 식별용 연락처는 표시되지 않는다.
5. 변경 적용·완료 후 이력 — 실행 검증 제외. 실제 회원 권한을 바꾸지 않았으므로 성공·실패 및 갱신 결과를 직접 검증하지 않았다. 화면에서는 빈 이력을 확인했고, 이력이 있을 때의 표시 항목은 코드로 검토했다.

## 우선순위별 제안

| 우선순위 | 문제와 근거 | 제안 |
|---|---|---|
| P1 | 2단계에서 목록과 상세의 상태 정보가 달라 보인다. 목록은 `is_active`만 확인하고, 폼은 시작일·종료일까지 확인한다. | 공통 상태 판정으로 통일하고 `이용 중 / 시작 전 / 만료 / 비활성` 배지, 기간, 변경 불가 이유를 표시한다. `변경 가능 회원만` 필터도 제공한다. |
| P1 | 3단계에서 대상과 기수가 자동 선택된다. 코드는 제목의 공통 접두어 길이로 후보를 정렬한 뒤 첫 항목을 선택한다. | 대상 프로그램과 기수는 미선택으로 시작한다. 추천이 필요하면 추천 표시만 하고 운영자가 직접 확정하게 한다. |
| P1 | 4단계 확인창에 기수가 빠진다. 3단계의 기수 선택에도 시작일이 없다. | 변경 전/후를 각각 프로그램·기수·기수 시작일로 구분한다. 실제 이용 시작 시점과 기수 시작일은 별도 항목으로 표시한다. 회원 연락처와 유지되는 종료일도 함께 보여준다. |
| P2 | 1단계는 검색하지 않으면 전체 회원을 긴 카드 목록에서 찾아야 한다. 목록에는 대표 프로그램 하나만 보인다. | 현재 프로그램·상태 필터, 활성 이용권 수, 전화번호 뒷자리 등을 제공한다. 목록 높이를 제한하고 검색·페이지 이동을 쉽게 접근하도록 구성한다. |
| P2 | 3단계의 대상 선택은 긴 이름을 단일 select에서 구분해야 한다. 공통 프로그램과 개인 전용 프로그램이 섞여 있다. | 검색 가능한 선택창으로 바꾸고 지점·유형을 분리 표시한다. 개인 전용 프로그램 포함 여부는 운영 정책을 확인해 필터 또는 별도 그룹으로 처리한다. |
| P2 | 빈 이력은 명확하지만, 소스상 이력이 있어도 프로그램명·변경자·시각만 표시한다. 기수·사유는 표시되지 않는다. | 이력에 변경 전/후 기수, 종료일, 변경 사유를 제공한다. 우선 읽기 전용 상세부터 추가하고, 되돌리기는 별도의 검증된 변경 절차로 설계한다. |

## 변경 영향 설명

현재 “기록과 피드백 유지” 안내와 종료일 표시는 장점이다. 다만 DB 함수는 기존 이용권을 비활성화하고 새 이용권을 만들며 앱의 선택 프로그램도 새 프로그램으로 바꾼다. 확인창에는 “기존 프로그램 이용권 종료 → 새 프로그램 즉시 이용” 및 “앱의 선택 프로그램도 변경”을 명시하는 편이 이해하기 쉽다. 운동 기록을 새 프로그램으로 이동하는 것으로 오해하지 않도록, 기록의 실제 조회 방식에 맞춰 문구를 정리해야 한다.

## 접근성 및 반응형 확인 범위

- 검색과 프로그램 선택에 접근 가능한 이름이 있으며, 회원 버튼에는 선택 상태와 키보드 포커스 스타일이 구현되어 있다.
- 확인 모달을 열면 취소 버튼에 포커스가 갔다. 취소 후 AX 관찰에서는 페이지 루트가 포커스로 보고되어, 실제 키보드 탐색에서 확인 버튼으로 포커스가 돌아오는지 추가 검증이 필요하다.
- 이름·기간 같은 핵심 정보 외의 보조 문구가 작고 옅다. 대비 수치와 확대 화면은 측정하지 않았으므로 접근성 위반으로 단정하지 않는다.
- 모바일은 이번 실행에서 캡처하지 않았다. 코드상 좁은 화면에서는 10명 목록 뒤에 변경 폼이 배치되므로 회원 선택 후 상세가 화면 아래에 남을 가능성이 있다. 모바일에서는 회원 선택과 상세를 단계별 화면 또는 시트로 분리하는 방안을 검증할 만하다.

## 코드로 추가 확인한 사항

- 대기 중인 대상 이용권 처리: UI는 현재 활성 이용권만 후보 제외에 사용하지만 DB는 시작 전 이용권도 중복 대상에 포함한다. 따라서 시작 전 권한이 있는 프로그램이 UI에서 선택 가능하다가 적용 단계에서 거절될 수 있다. 재현은 하지 않았으며 UI/API의 자격 판정 통일이 필요하다.
- 조회 실패와 빈 상태 구분: 회원 상세 조회에서 일부 쿼리 오류를 검사하지 않고 빈 배열로 처리한다. 네트워크/DB 오류 때 “활성 프로그램 없음” 또는 “이력 없음”으로 오인될 위험이 있다. 이번 빈 화면의 원인이 조회 오류였다고 확인한 것은 아니다.
- 검색 비용: `getAdminAllUsersPage`는 인증 사용자 전체를 읽은 뒤 필터·정렬·페이지 분할한다. 규모가 커지면 검색이 느려질 수 있어 서버에서 검색과 페이지 분할을 수행하는 전용 조회를 고려한다. 실제 지연 시간은 측정하지 않았다.
